## A — One additive, read-only selection-preview contract (recommended)

Replace the unadopted GET-only proposal with ONE separate `POST /api/v1/fulfillments/:id/allocation-preview`. It returns at most100 eligible options for one selected saved Claim plus at most100 per-Line assessments for the actual current selections. Keep existing DRAFT/release-aware batch recommendation APIs/DTOs and all actual write command schemas/algorithms/replays unchanged. Do not add a bypass flag to a prepare/write API.

### Strict request and saved authority

Body: `{version,selectedClaimId,page,selections,lineReasons}`. Version is current positive uint32, selectedClaimId a canonical safe positive saved Claim ID, page positive safe integer. `selections` has≤5000 unique `{claimId,allocations}` entries; each allocations list has≤50 unique positive `{inventoryBalanceId,expectedBalanceVersion,baseQuantity}` legs, total submitted legs≤5000. Quantities are canonical positive integer strings≤MAX_SAFE_INTEGER; CAS is positive uint32. Omitted/empty Claim selections represent an incomplete editable preview only, never a zero write/default/dummy effect. `lineReasons` has≤100 unique `{fulfillmentLineId,reason}` entries; reason is bounded500 Unicode codepoints with existing control restrictions, and may be empty during editing.

All Claim/Line IDs are selectors validated against the locked target's complete saved source set. No caller-supplied eventId, purpose, Reservation/SO/warehouse/source identity, old releases, credits, expected source facts or eligibility policy. Server derives the ALLOCATE(DRAFT) or REALLOCATE(unpicked PICKING/no active Shipment) purpose, actual sources, true Line/Reservation writer order and complete old effects. Unknown/foreign/duplicate identities or malformed request are rejected with stable400; unavailable schema, incomplete/corrupt owner source/completed-operation proof or malformed owner result fails closed with the existing safe503/critical boundary.

Fresh view+operation authorization at entry and before return, actual trusted RC transaction metadata, Sales→Fulfillment→Inventory parent/root/resource locks, exact sets/current CAS and all existing quantity/source proofs remain. Reallocate proves/credits ALL positive current own effects before any prefix simulation or selected-Claim filter; foreign effects never grant credit. DRAFT credit is exactly0. Validate full100Lines/50members perLine/5000member source bounds despite returning only one Claim's options.

### Actual-prefix owner semantics

Reuse existing Inventory eligibility/ranking SQL and selection assessor. Starting from actual physical free plus strictly proved all-own releases, simulate each prior Claim's ACTUAL selected complete quantities in authoritative writer order in memory. Never consume the default-prefix recommendation instead. The selected Claim's current choices and all later choices do not deplete its displayed options. Independently apply its actual source/minimum-life/policy filters, current initial Balance CAS and owner ordering before bounded100+1 pagination. Show physical0 only when valid own credit makes availability positive. No frontend eligibility, rank, expiry, physical budget or release-credit calculation.

An incomplete earlier Claim or stock-invalid/stale-CAS earlier selection makes that prefix explicitly NOT_READY and suppresses invented downstream options/classification. It does not silently fall back to default recommendations or discard the invalid selection. Reason/FEFO permission deficiencies are separate readiness facts: a stock-feasible complete actual selection still determines the conditional in-memory prefix even when its reason/permission prevents submission. Nothing is reserved by this read.

Assess the full current selection against all saved Claims/Lines, exact requested quantities, aggregate actual stock use, real initial CAS,≤50 selected legs perLine and≤5000total, reasons and FEFO permission. Final `canSubmit` is true only when EVERY Line is complete, stock/source/version valid and permitted with exactly the required reasons. Partial/invalid preview must never be passed to an existing writer as a command.

### Separate strict public DTO and UI binding

Response: `{fulfillmentId,version,purpose,warehouseId,asOf,selectedClaim,assessments,canSubmit}`. `selectedClaim` contains owner-derived `fulfillmentLineId,claimId,inventoryReservationId,skuId,expectedReservationVersion,requestedQuantity,minimumRemainingDays,baseUom,page,hasMore,prefixStatus,options`. Prefix status is READY/INCOMPLETE/INVALID. Options≤100 carry `inventoryBalanceId,binId,binCode,lotId,expiryDate,firstReceiptDate,fifoAnchorDate,physicalFreeQuantity,ownReleaseCredit,priorSelectedQuantity,availableQuantity,expectedBalanceVersion,selectionStrategy,rank,eligible:true`. Quantities remain exact integer strings, available=physical+own credit-minus ACTUAL earlier consumption and must be positive; physical/credit and prefix consumption must remain distinguishable (use owner-derived `priorSelectedQuantity` rather than presenting a virtual value as physical). Initial CAS is never a simulated future version. No recommendations/batch completeness are repurposed into this DTO; the old batch read supplies defaults.

Each assessment names its saved Fulfillment Line and reports `selectionStatus:READY|INCOMPLETE|INVALID`, `overrideType:NONE|FIFO|FEFO|UNKNOWN`, `reasonRequired:boolean|null`, `reasonStatus:NOT_REQUIRED|REQUIRED|VALID|UNUSED|UNKNOWN`, `fefoPermission:NOT_REQUIRED|GRANTED|DENIED|UNKNOWN`, at most100 safe issues `{code,claimId:null|savedID,inventoryBalanceId:null|selectedID}` using existing bounded public codes, and per-Line `canSubmit`. If any member/prefix cannot be assessed, overrideType is UNKNOWN and reasonRequired null (never false NONE); otherwise FEFO takes precedence over FIFO, then NONE. Reason/permission deficiencies make canSubmit false without corrupting stock budgets. No source-proof internals enter public output; do not expose SQL, financial/customer-sensitive data or fabricated authority.

UI invalidates the assessment on every selection/reason/root-version/actor/permission change, aborts/ignores stale reads, and freezes/captures the exact assessed body before a write. Only a matching current owner assessment may enable submit. Missing FEFO permission is visibly explained and disables submit; FIFO/FEFO reasons are based on owner assessment, not independent ranks/default differences. Existing owner write remains the final authority and revalidates everything. New event/journal belong ONLY to an explicit actual write, never preview. Unknown write results retain original assessed intent/event for exact replay; explicit reload preserves old input for reconciliation without silently changing choices/CAS.
