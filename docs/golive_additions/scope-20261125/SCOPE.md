## 4. 共同規則

沿用應收及應付已在main的做法：一個命令一個交易；`event_id`唯一的操作表防重（退貨模組新增自己的操作表，貸項及退款用應收／應付現有的操作表）；年度流水號；金額`DECIMAL(19,4)`以BigInt計；狀態及代碼用`ascii_bin`的`CHECK`；操作者為`users`外鍵加顯示名稱；操作記錄不可改。死結及鎖等待逾時整個交易回滾並回可重試的409。新權限照`0125`授予系統管理員，並處理受新權限影響的既有測試。

**跨模組的一條總規則**：每個命令先取來源模組的序列化點（出貨列或採購單列），再取本模組的列，最後才進Inventory；Inventory在自己的次序最後取成本池；呼叫方在Inventory返回之後不再取新的鎖。下面各節是這條規則的具體化。

## 5. 存貨成本（片C）

### 5.1 規則

- **成本池**：每個SKU一列（兩倉、所有存貨狀態、在途合計），存計價數量及港幣帳面金額；單位成本＝金額÷數量，不另存。調撥、移位、狀態轉換（隔離↔可用）、預留及分配**不動成本**。
- **收貨**：入池金額＝實收基本數量×已鎖採購行單價÷採購單位換算因子，half-up到四位小數（`purchase_order_lines.unit_price`，已核`0113`）。應付改價不重估。
- **非港幣收貨**（TL裁定，Codex TL `5c40ccfc`，作者同意）：成本功能啟用後仍可建立其他幣別的採購單及收貨草稿；確認時以已鎖採購單幣別為準，非HKD在Inventory過帳前整張拒絕（409，訊息說明此採購單非港幣），累收量、庫存及成本都不變；既有成功的重送取原結果。
- **出庫**（出貨、負調整、盤虧）：出池金額＝池金額×出庫數量÷池數量，half-up到四位小數；出庫數量等於池數量時取池內全部餘額，所以數量為零時金額必為零（與應收剩餘池同一做法）。
- **沖銷及退回按原值**：
  - 出貨沖銷、客戶退貨收回：按原出貨異動的成本流水金額，按數量比例回入；同一原異動的最後一筆回入取其餘數。
  - 收貨沖銷、退回供應商：按原收貨異動的成本流水金額，按數量比例出池，但不超過當時池內金額；若令池數量歸零，取池內全部餘額。原值與實際出池的差額記在成本流水上供對帳。
- **沒有原成本的情況**（成本啟用前已存在的庫存；正式驗收庫`e9156999`就有）：沖銷或退回的原異動沒有成本流水時，按當時池單位成本計，`original_entry_id`為空；出庫數量大於池的計價數量時，取池內全部金額，不足的數量記為「未計價數量」，池歸零而不變負。估值報表列出未計價數量。正式上線以決定B確保期初已有成本，這兩種情況只應在測試及切換前出現。
- **正調整及盤盈**：按當時池單位成本入池；池數量為零時按該SKU最近一筆成本流水的單位成本；從未有成本即拒絕。（`inventory.md`主張盤盈須另填核准成本；作者取不另填的做法以免新增輸入及權限，見`DECISIONS.md`第3節。）
- **期初**：期初CSV加「單位成本（港幣）」，存在現有預檢紀錄的JSON內，**不加資料欄**（`inventory.md`，作者同意）；期初過帳時每行寫一筆期初成本流水。財務須在G3結案前簽核兩倉的數量及金額。
- **啟用**：成本表存在之後，所有改變數量的過帳都必須寫成本流水，沒有半開狀態；在此之前沖銷及退貨只動數量。

### 5.2 鎖序

已核：Inventory所有改變數量的命令都經`InventoryLockService.lockForCommand`（倉庫 → 庫存控制列 → 庫位 → 庫位鎖 → 批次 → 結存 → 預留 → 調撥 → 盤點，`InventoryLockService.js:198–255`）；收貨新批次路徑另在其後以`lockBalancesAfterLot`鎖新結存（`InventoryPostingService.js:645,668`）。

裁定：**成本池列在Inventory該次呼叫的最後取得**——所有存貨鎖（含`lockBalancesAfterLot`）之後、寫異動之前——按`sku_id`升序，先插入不存在的列再`FOR UPDATE`，由一個共用函式做。不可放在`lockForCommand`內，否則收貨新批次路徑會變成「成本池 → 結存」，與其他命令相反。按SKU計（不分倉）令兩倉同一SKU的過帳在同一列上排隊，以20人規模接受。「最後」是以**整個交易**計，不是以一次呼叫計：若同一交易內有兩次改變數量的Inventory呼叫，第二次的存貨鎖就會落在第一次的成本池鎖之後。所以每個交易最多一次改變數量的Inventory呼叫（多行時合為一批）；Inventory、Fulfillment（含沖銷Phase B）、Purchasing及Returns各自須核對自己的交易，以及Inventory返回後只寫已鎖或新插入的列。本節只按來源閱讀，沒有執行。

## 6. 沖銷

### 6.1 出貨沖銷（片SR）

TL裁定已發（`993fb7da`）：只做「一律拒絕」版本。出貨的任一出貨行在未取消、未作廢的應收發票上（草稿或已確認：`ar_invoice_lines.active_shipment_line_id`不為NULL），或該出貨有任何未取消的客戶退貨單，即拒絕；任一方無法判定即拒絕。在Phase A持有`shipments`列`FOR UPDATE`之後查。應收及退貨各提供一個在呼叫方交易內執行的只讀provider（`findShipmentInvoiceClaimsInTransaction`、`findShipmentReturnsInTransaction`）；應收建立及確認、退貨單建立都先鎖同一出貨列，應收取消及作廢只會減少佔用，所以普通讀取已足夠。公開route在兩個provider都註冊前不註冊；`NO_PROVIDER_REQUIRED`在應收已上線的部署不再成立。11-19裁定仍適用：沿用已合併的兩階段核心，**Recovery Job必須註冊**（這是背景工作；先前首期「不做背景工作」的原則對沖銷不適用）。成本由Inventory在其現有沖銷過帳內按原值回沖，Fulfillment不傳也不讀成本。這取代了應收SCOPE §3.1「首期不開放公開出貨沖銷」的前提；應收開票的鎖序不變。

### 6.2 收貨沖銷（片GR）

鎖序：操作列 → 採購單（`FOR UPDATE`）→ 採購行 → 收貨表頭 → 收貨明細 → **應付佔用檢查** → **數量上限檢查** → Inventory（含成本池）→ 寫更正單、收貨及採購單進度、稽核（`purchasing.md`，沿用採購設計§3.7、§4.12–4.13）。

- 應付佔用檢查：該收貨的任一收貨行在未取消、未作廢的應付發票上（`ap_invoice_lines.active_goods_receipt_line_id`不為NULL）即拒絕。應付建立發票先鎖同一採購單；應付取消及作廢不鎖採購單、只減少佔用，所以普通讀取已足夠。這是應付SCOPE r10 §3.1承諾「開放沖銷時連同釋放路徑一併重審」的結果：**釋放路徑不需改動**。貸項單不釋放佔用。
- 數量上限：每個收貨明細「已沖銷＋已過帳退回供應商＋本次 ≤ 實收」；收貨沖銷及退回供應商都在同一採購單鎖下檢查同一上限（`returns.md`的建議，採納）。同一收貨可以先後有沖銷及退回，只要合計不超過實收。
- 「應付未安裝」provider只在`ap_invoices`表不存在時可用；應付已上線的部署未註冊真實provider即啟動失敗。

## 7. 退貨、貸項單及退款

### 7.1 界線

退貨單（實物）、貸項單（金額）、退款（現金記錄）是各自過帳的單據，只以來源ID連結，**不自動產生**。銷售一側不加表，只讀連結（`sales.md`）。

### 7.2 客戶退貨

- 來源是一張`SHIPPED`的出貨單；可分多張退貨單。每行引用原發出明細`shipment_issue_details`（已核`0097`，其`inventory_movement_id`即原出貨異動），累計退回不超過原發出量。
- 鎖序：操作列 → 出貨列（`FOR UPDATE`，與應收開票及出貨沖銷同一點）→ 退貨單 → Inventory（收回入隔離區；成本按原出貨異動回入）→ 寫退貨單。退貨單草稿建立時同樣先鎖出貨列，所以出貨沖銷的Phase A能可靠地看到它。
- 隔離放行為可用：沿用Inventory現有的狀態轉換，不動成本。客戶退貨不改應收發票。

### 7.3 退回供應商

- 來源是一張已確認的收貨；每行引用原收貨明細，上限見6.2。
- 鎖序：操作列 → 採購單（`FOR UPDATE`）→ 收貨表頭 → 收貨明細 → 退回單 → Inventory（出庫；成本按原收貨異動，5.1）→ 寫退回單。
- 已開應付發票的收貨**可以**退回供應商（業務退貨，不是更正）；金額由應付貸項單處理；退回不釋放應付佔用。應付發票仍按整張收貨的實收數量（應付r10，Sam已批准），不因先退回而減少；退回後若供應商發票已扣除退貨，入帳人員以改價或貸項對齊（見`DECISIONS.md`第3節）。
- 這取代了應付D8（按未佔用數量沖銷）：D8是為按數量開票設計的；整張開票下，沖銷一律被有效發票擋住，退回則不受發票影響。

### 7.4 貸項單（應收、應付對稱）

- 一張貸項單只對一張已確認的原發票，每行引用一個原發票行，每行一個金額，可附數量（只供顯示及退貨連結）。同一原發票行的已確認貸項累計不超過該行金額。可連結本側已過帳的退貨行。
- **期初發票**（應收G1、應付沒有）沒有發票行：只容許一行、不引用發票行的貸項；不計入按SKU的毛利（`apar.md`指出G1期初發票無原行）。
- 金額：貸項行金額四位小數，每行不超過原發票行金額；貸項單總額＝各行之和half-up到幣別小數位（與發票總額同一規則），所以全額貸項的總額等於原發票總額。
- 確認時：以貸項金額沖減原發票未付額（不超過當時未付額），寫一筆對原發票的核銷；其餘為貸項單的「可用額」，可核銷到同往來方、同幣別的其他已確認發票，或作退款。對原發票的那筆核銷不可單獨解除，只在作廢貸項單時一併撤銷。
- **發票表不加欄**（TL裁定，與`returns.md`建議的`credit_applied_amount`不同）：貸項的核銷與收款／付款的核銷同樣計入發票現有的`allocated_amount`，所以`outstanding_amount = total_amount − allocated_amount`的`CHECK`、帳齡、Business Master及Supplier的未付檢查、發票作廢「須先解除全部核銷」的規則都不變，已合併的收款／付款程式不用改。代價：發票的`allocated_amount`不再只代表現金；發票詳情及報表須分別列出兩種核銷（各有自己的表，可分辨）。已核：main的應收發票詳情及應付發票詳情（`62fd35f7`）都把這一欄標為「已核銷」而不是「已收／已付」，發票列印（G5）不顯示它；`codex-erp-app-apar-01`須確認沒有其他地方把它當作現金。
- 鎖序：建立草稿：操作列 → 原發票（`FOR UPDATE`，驗累計上限）→ 插入。確認：操作列 → 貸項單 → 原發票 → 核銷 → 編號。核銷到其他發票：貸項單 → 發票（ID升序）→ 核銷，與收款／付款的「單據 → 發票」同方向，沒有命令先鎖發票再鎖貸項單。作廢貸項單：須沒有對其他發票的有效核銷及有效退款；鎖貸項單 → 原發票，撤銷對原發票的核銷。原發票作廢照現行規則（`allocated_amount`須為0，所以須先作廢貸項單）。
- 現有表須改的只有兩類`CHECK`：應收／應付編號表的文件種類加`CREDIT_NOTE`、`REFUND`；操作記錄表的對象類型加`CREDIT_NOTE`、`CREDIT_APPLICATION`、`REFUND`（已核`0123:34,225`；應付`62fd35f7`的`0129:31,240`）。不改資料，不加欄。
- 這實現了應付D5及應收r3的「依原發票行沖減、超額成同幣別貸項餘額」；不做r3的出貨來源分配及沖銷證明。

### 7.5 退款記錄

- 客戶退款：從應收貸項單的可用額付出；供應商退款：從應付貸項單的可用額收回。只記錄（日期、金額、方式、參考號），不產生銀行檔。
- 來源只限貸項單。未核銷收款的退款屬預收款，第二期（Sam）；應付付款未核銷額由供應商退回，本輪不做（付款記錯可作廢）。
- 鎖序：操作列 → 貸項單 → 退款 → 編號。作廢退款：可用額加回。
