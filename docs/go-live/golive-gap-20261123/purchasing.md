# 採購與收貨上線差距

基準為 11/23 的 main `c6df403e`。以兩倉、約 2,000 個 SKU（含批次）、約 20 人及全公司每日最多 1,000 張訂單評估。

## 1. 已可用（P01–P05 主流程以外）

- 採購待審清單、撤回待審後重提、駁回回草稿及審批回應遺失後重試。已用真瀏覽器驗證。
- 供應商選單正式名稱回落、封鎖草稿提示；封鎖後例外收貨、隔離、低效期放行及超收理由。已用真瀏覽器驗證。
- 未完成採購單查詢 API，支援逐行到貨日、逾期及分頁。已用登入帳號在預演環境實測 API。
- 採購單複製、草稿／正式 A4 列印，以及收貨草稿取消。主分支有入口，未找到這三項的真瀏覽器證據。

## 2. 上線首日會缺什麼

| C 未收追貨、收貨篩選、CSV（038–039） | 缺逐行交期的追貨頁、收貨日期／倉庫／風險篩選及 CSV。暫以 PO 的「仍有未收」、單張收貨歷史及人工追貨表處理。 | 3–5 | 採購／否 |
| D 跨單據稽核（026、038） | 操作者、原因及動作不能集中查找。暫以單據歷史、庫存異動及支援人員查既有稽核記錄。 | 2–3 | 採購／否 |
| E 收貨逾時查明結果（033–034） | 畫面可用原操作重試，尚無先查原操作的流程。可在同頁同操作重試，或回讀原收貨單及庫存異動。 | 1–2 | 採購／否 |

| H 進階權限與競態驗證（041–042） | 匯出、沖銷及跨單競態仍缺完整證據。現有操作有角色預演、交易整合與回滾證據。 | 2–3 | 身分權限及庫存／否 |
| I 舊規模容量驗證（043） | 缺 50k CSV、超大單據的容量證據。日常用分頁及逐單作業，有實際瓶頸再按觀測規模估算。 | 3–5 | CI 及資料庫／否 |

## 3. 已知缺陷及限制

11/23 預演補驗未新增採購缺陷。採購清單的供應商／採購員選項只列目前頁資料，可手輸 ID。收貨列表畫面目前只按狀態篩選，可從 PO 找該單的收貨歷史。Sam 已決定收貨沖銷留第二期，首日更正仍需主管接手及 PO 與庫存對帳。

## 4. 建議分級

- **上線前必須** · A 讓採購員能關閉取消或短交後的餘量，避免兩倉照舊單誤收。G 讓在途貨各有唯一入帳路徑，並確認錯帳有人處理及資料可還原。
- **上線後首月** · B 按第二期安排，優先補齊批次錯帳的完整更正。C 減少每日人工追貨。D 縮短例外追溯。E 減少逾時後人工查單。H 隨新功能補齊其權限及競態驗證。
- **可以不做** · F 已可按收貨單查供貨，人工維護足以支援首期。I 依目前規模，按實際瓶頸決定是否啟動。
