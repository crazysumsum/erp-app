# 使用者與角色管理｜上線差距清單

2026-11-23，基準 `main c6df403e`。瀏覽器欄引用既有 Playwright／UAT 證據。

## 1. 已可用

- 使用者管理。建帳、指派角色、停用與重新啟用均經真瀏覽器驗證，亦確認停用後原工作階段失效、重新登入遭拒。
- 角色管理。建立角色、授權後重載、業務帳號越權拒絕均經真瀏覽器驗證，含 UAT-001 的六組 21 項權限。
- 設備審批與首登改密。登入後顯示待核准、管理員核准、強制改密及重登經真瀏覽器驗證。拒絕設備、管理員重設密碼的完整瀏覽器操作未核得證據。
- 變更紀錄。真瀏覽器驗過建帳、配角、改密與停用／啟用的紀錄讀回。
- 個人資料可改顯示名稱及查閱自己的設備。程式已核對，未核得真瀏覽器操作證據。

## 2. 上線首日會缺的功能

| 項目 | 用戶做不到／暫用方式 | 估計工作天／依賴／改表 |
|---|---|---|
| 設備撤銷介面 | 審批者無法在管理頁查閱及撤銷已核准設備。遺失時由持有設備管理權限的值班人員使用既有 API，必要時先停用受影響帳號。 | 2–3 天／設備綁定、權限／否 |
| 緊急核准稽核 | `approveDevice.js` 只在設備列留 CLI 備註，變更紀錄頁查不到具名操作者及原因。暫由值班人員登記工單、設備 ID 與原因。 | 0.5–1 天／部署、使用者稽核／否 |
| 待審通知與敏感操作告警 | 使用者不能自動通知審批者，管理員也收不到即時告警。暫用公司既有聯絡管道及人工巡查。 | 2–4 天／IT 通知管道、設備與稽核／否（單一通知管道） |
| 自設初始密碼 | 新員工無法以一次性連結自行啟用。管理員私下交付臨時密碼，由本人首登改密。 | 3–5 天／登入、私密交付管道／是（一次性憑證雜湊及效期） |

## 3. 已知缺陷及限制

- 首個管理員須先用既有 CLI 核准設備。換瀏覽器或清除資料需重審。臨時密碼 72 小時過期，同 IP 集中首登曾遇 429，按 `Retry-After` 接續。
- 一般業務頁收權最遲等一次續期（預設 15 分鐘）。緊急收權可停用帳號以撤銷工作階段。登入預設閒置 30 分鐘、最長 8 小時後需重登。

## 4. 建議分級

- **上線前必須** — 具名正副管理員，預先核對角色並分批完成首登、設備核准、改密。演練緊急核准與撤銷並記錄工單，避免員工當日無人開通或受阻。估計 0.5–1 天，依賴 IT 與各部門角色負責人，無需改表。
- **上線後首月** — 補設備撤銷介面及緊急核准稽核。首日暫用方案須有具名值班且通過演練，否則設備撤銷需要提前。
- **可以不做** — 新增通知可由人工巡查與現有聯絡管道替代，若反覆延誤再排入首月。一次性啟用連結可由逐人私下交付與首登改密替代。約 20 人可先沿用現有稽核查詢，外部防竄改副本與大規模批次、容量驗證可不列上線條件。
