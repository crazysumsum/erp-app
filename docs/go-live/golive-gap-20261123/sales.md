# Sales 上線差距清單｜2026-11-23

基準 `main c6df403e`。約 20 位使用者、每日最多 1,000 張訂單、兩倉、約 2,000 SKU（含批次）。兩條閉環據 PM 已分段實機通過 17/17。以下瀏覽器結果為既有功能驗證。

## 1. 已可用（閉環外）

- 手工建立／修改草稿、報價列印與取消（真瀏覽器驗過）。
- 缺貨承諾、Backorder FIFO 補配、撤回／取消／關閉剩餘（真瀏覽器驗過，含部分庫存及失敗場景）。
- CSV V1 模板、預檢、確認、來源去重、例外及逐張結果下載（真瀏覽器驗過）。
- Sales 訂單／未完成查詢、唯讀歷史與審計紀錄（真瀏覽器驗過）。

## 2. 首日差距

下列均為工作天估計，含最小功能驗證。

| 差距與替代做法 | 估計／依賴／資料表 |
| --- | --- |
| 渠道來單與切換日未交付訂單。現有 CSV 可接手，需將來源欄位映射至主檔、按出貨倉分流，逐批核對成功／失敗／重複數。如有部分出貨的舊單，留舊流程結清，避免重複預留或出貨。 | 1–2 天設定與演練／Sales Ops、Customer、Item、Inventory／不改表。 |
| 訂單清單無 CSV 匯出，從訂單只能看到外部來源編號，沒有直達匯入批次。可用查詢篩選、匯入結果 CSV 或人工抄錄小量清單。 | 3–5 天／Sales／小量匯出及批次連結預估不改表。 |
| 出貨確認後無公開沖銷；沒有完整的系統內替代。錯單須隔離、登記並暫停後續開票，由倉庫及應收共同對帳。 | 5–8 天／Fulfillment、Inventory、AR、Sales／已有沖銷表，預估不改表，待契約確認。 |
| 信用額度尚無應收曝險硬擋。財務可用帳齡及未開票清單人工覆核，必要時設 `ON_HOLD`。 | 3–5 天／AR、Customer／採唯讀計算預估不改表。 |
| P4 歸檔、背景大匯出及專用對帳／告警未交付。歷史單仍可在「已結束」查詢，日常對帳可用訂單、出貨與應收清單抽核。 | 8–15 天／Fulfillment、Inventory、AR、運維／歸檔、匯出工作需新表。 |

## 3. 已知缺陷及限制

截至基準未找到阻斷 Sales 主流程的已知缺陷。每張 SO 固定一倉，須兩倉共同供貨時先在來源分單，為各子單保留穩定且不同的外部訂單號。已有履約歷史不可撤回，先處理未結履約再按狀態關閉剩餘。CSV 上線仍須核實實際角色、欄位映射及排程。

## 4. 建議分級

- **上線前必須**：演練 CSV／未交付訂單切換、兩倉分流與錯出貨隔離，確認批次結果有人負責。若不能接受人工隔離，須先決定最低沖銷範圍。現無證據需要新增 Sales 功能才能完成首日流程。
- **上線後首月**：小量匯出及匯入批次連結可省日常整理時間。若錯出貨率高或信用人工覆核積壓，再優先排受控沖銷或曝險整合。
- **可以不做**：本次不需平台專屬即時 Adapter、多倉自動拆單、P4 歸檔、大匯出／額外恢復框架或規模壓測。現有 CSV、人工選倉與歷史查詢可維持日常作業。
