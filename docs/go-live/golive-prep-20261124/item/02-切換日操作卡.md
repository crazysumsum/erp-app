# 切換日操作卡｜貨品主檔

| 時點／負責人 | 要做的事 | 怎樣確認完成 |
| --- | --- | --- |
| 截數前／商品資料負責人、營運 | 定凍結時間及唯一正式清冊，凍結舊貨品主檔。截止後新增或修改集中登記，由一人補錄。營運確認正式目標的備份、可還原方式及回滾決策人。 | 記下截數時間、版本、總 SKU 數、各類手補筆數、備份及負責人。 |
| 匯入時／Item 管理員 | 確認分類、品牌及單位；只新增模式上傳 Standard CSV，核對預檢，再確認匯入。用畫面建 Variant、補單位、條碼和效期，啟用要交易的 SKU。 | 保存每檔工作編號及結果檔。用匯出清單比對唯一代碼、SKU 筆數及狀態，試查代表性 SKU／條碼，核對一筆箱入換算和一筆批次效期 SKU。 |
| 期初入帳前／商品資料負責人、Inventory | 兩倉都用同一份 SKU 主檔。逐筆核對 SKU 代碼、已啟用、基本單位、追蹤政策。箱數由 Inventory 按核准換算轉成基本單位，批號、到期日及實存數留在庫存檔。 | 兩方簽認差異清單已清零，或 PM 已接受明確排除的範圍，才把可以入帳的版本交 Inventory。由 Inventory 負責期初入帳、對帳及結案。 |
| 開放後／商品管理員、值班營運 | 經同一負責人補登凍結期間的變更，再用精確 SKU 代碼及條碼抽查銷售、採購選得到預期貨品及單位。 | 登記累積補錄、操作人、處理結果與兩倉交接人。 |

## 例外處理

- **預檢不通過或匯入結果不明。** 先查工作編號、狀態、結果檔及 SKU 是否存在。已完成的批次不要重送。確認未套用後，修正差異並重新預檢；先阻止受影響 SKU 入帳。仍有疑問交 Item 負責人查核，不直接改資料庫。
- **已入帳才發現錯單位、錯追蹤或缺批。** 暫停受影響 SKU 的後續作業，保留原單據，交 Inventory／PM 決定核准的調整流程。已受引用保護的屬性不可硬改，期初已結案時由 Inventory 按正式調整流程處理。
- **Supplier 供應歷史未更新。** 保留已確認 GR 及入庫紀錄，用原單據核對供應商、SKU、數量及單位。登記差異並交 Purchasing／Supplier 跟進，避免為補歷史再收一次貨。

每件例外至少記下時間、檔案與工作編號或單號、SKU、倉庫／庫位、批號與效期（適用時）、原值／正確值、受影響數量、處置人及覆核人。正式清冊、匯出與例外台帳放在公司核准位置，勿放入 GitHub。
