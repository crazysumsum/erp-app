# 切換日的先後與放行條件

1. PM 與倉務、財務先定同一個截數時點，舊系統保留查詢。截數至開放期間收到的貨款、貨物及出貨指令逐筆登記，指定一人按原單核對補記。
2. 先備好幣別、付款條款、倉庫、庫位及操作人員權限。貨品和客戶、供應商名單可分組並行準備。入期初庫存前，先核對 SKU 的基本單位、換算、批次及效期。
3. 兩倉都完成期初入帳後，倉務按倉、庫位、SKU、批次、效期及庫存狀態逐項對帳，記下最後版本供 Sam 簽核。簽後又有一批入帳，就重新對帳簽核。
4. 用簽核版本一次關閉兩倉的期初入口。正式結案後，漏批走有原因及單據的授權調整。舊的預檢工作仍可查，不能再入帳。
5. 客戶、幣別、舊帳清單及登記權限備妥後，財務即可與庫存組並行登記期初應收。核清舊號長度與重號範圍後才載入；逐張核舊號、日期、到期日及截數餘額，再按客戶和幣別核張數與總額。簽認後收回登記權，才核銷截數後收到的款。
6. 未交付銷售單可先整理，確認會預留庫存，應排在兩倉結案後。訂單按履約倉分流；總預演每倉各走一筆批次出貨，核對庫位、批號、效期及扣帳。
7. 對每張部分出貨或部分收貨的舊單，列出原單號、未交或未收餘量、接手人、唯一入帳系統。請 Sam 確認草案中「舊單留舊系統完成」與「截數後一律新系統入帳」的適用界線；留舊單的實物流轉仍須與新庫存對帳。
8. 開放日常收貨、出貨及核銷前，由倉務、財務分別簽認，PM 核對截數期間的待補單。簽核前有差異就暫停開放；已有正式交易後需逐單核對及更正，不能直接還原舊備份。
9. 草案第 2、5、6 節可更新：G2–G4 已通過分支評審；G5 已確定要做。確認發票須有客戶預設帳單地址，正式列印須有公司名稱及付款資料；部署時填入，開放前試印。公司樣本已非開工前置。
10. 在凍結版本驗收清單補列 Supplier UI 分支的受影響流程，與兩條閉環及 G1–G5 一起驗收。正式資料、核對清單與銀行資料只放受控位置，公開倉庫僅存指引及合成範例。
