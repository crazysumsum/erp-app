# 應付切換及例外操作卡

本卡供財務入帳、付款及覆核人員處理上線後第一批單據。示例均為合成資料。正式發票、付款憑證和例外台帳存放在公司的受控位置。

| 何時／誰做 | 操作及完成證據 |
| --- | --- |
| 開始前／財務覆核、採購及帳號管理員 | 確認應付模組已放行、首批供應商及幣別已備妥，入帳和付款帳號可在獲核准裝置登入。以首批收貨號對照 ERP 已確認收貨，標記上線前舊欠款及未能在 ERP 開票的例外。 |
| 收到發票／入帳人員 | 在「應付發票 → 登記應付發票」選「由收貨開票」，搜尋並勾選同一供應商、同一幣別的整張已確認收貨。一張供應商發票可合併多張符合條件的收貨。無採購單的上線後發票選「無採購單發票」，選啟用中的供應商和幣別，填原因、到期日及實際費用行。 |
| 確認發票／入帳人員及覆核者 | 核對發票號碼、發票日期、到期日及供應商發票總額。真實另列的正數收費可加費用行。若個別收貨行的實際金額與採購單不同，交獲授權的人員按原件改該行金額並填原因。系統總額須與原件一致，到期日異於計算結果須填原因。確認後記下發票編號。 |
| 已完成出款／付款人員 | 由應付帳齡列、發票列表或詳情按「登記付款」，核對帶入的供應商和幣別。填實際付款日期、金額及方式，轉帳填參考號、支票填支票號、其他方式填說明。先存草稿、覆核憑證，再「確認付款」取得付款編號。無同幣別未付發票的預付款須用供應商搜尋，且供應商須已啟用。 |
| 核銷及對帳／付款人員、財務覆核 | 在付款詳情按同一供應商、同一幣別的發票輸入核銷額。可部分核銷或一次核銷多張。重開付款及發票詳情核對各自餘額，再按幣別核對帳齡。用原發票、ERP 發票編號、付款編號及憑證參考交叉核對。 |

合成核對例。供應商 `DEMO-AP-01` 兩張 HKD 發票分別為 225.00 及 100.00。一筆已確認付款 HKD 325.00 逐張核銷後，兩張發票未付額及這筆付款可核銷額應為 0.00，該供應商的 HKD 帳齡不再列這兩張。

## 例外

| 情況 | 處理方式 |
| --- | --- |
| 上線前的舊供應商發票 | 在原有受控台帳跟進發票及相關付款。若一份出款憑證同時涵蓋舊欠和新單，先交財務覆核各筆歸屬和金額，ERP 只登記屬上線後應付流程的金額。 |
| 整單折扣或扣減 | 已開草稿則保留待處理，由財務在受控台帳記錄原件、原總額、折扣或扣減、淨額和 ERP 草稿編號。按財務的既有系統外流程跟進。禁止攤入收貨行或用虛構費用使總額相符。 |
| 同一張收貨被供應商拆成多張發票 | 財務在受控台帳逐張記錄供應商發票號、金額、到期日及對應收貨號，依財務受控流程在 ERP 外處理該批發票和付款。核對台帳及付款憑證以防重付。避免合併發票或用無採購單發票重新登記同一債務。 |
| 發票日期打錯或在未來 | 草稿發票日期固定。先複核原件，抄錄需重填的行金額、原因及費用行，取消舊草稿，再用正確日期重新登記並交叉記下兩張草稿的單據連結或 ID。新發票日期在未來時，等單據日期到達才登記。若已有未來日期的草稿，須等到單據日期才可確認。若已確認後才發現日期錯誤，先由財務覆核，已核銷的先逐筆解除，再作廢並重建。只改到期日可在草稿直接更改，須填原因。 |
| 付款回應遺失或仍未確認 | 同一帳號回到原瀏覽器分頁，使用「重試原操作」核對結果。已收到明確業務拒絕時按畫面提示修正。若款項本身有疑問，先核對出款憑證，再交財務覆核。 |

例外台帳逐筆記錄供應商代碼、幣別、原發票號、收貨號、金額、到期日、例外類型、責任人、覆核人、憑證參考和結案結果。付款前以供應商、幣別及原發票號交叉查例外台帳與 ERP 清單。
