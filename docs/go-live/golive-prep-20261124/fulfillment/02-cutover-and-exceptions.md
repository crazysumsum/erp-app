# Fulfillment 切換及例外操作卡

## 截數當日

1. **Sales 與兩倉主管**記錄截數時間及舊單的最後出貨狀態，逐張標為「留舊」或「轉新」。已部分出貨的舊單留原流程結清。確認同一筆餘量只有一條出貨路徑，舊出貨單不載入新系統。
2. **兩倉主管**等期初庫存簽核、按 Inventory 程序結案，以及 Sales 確認訂單和預留。核對 SO、新舊單號、履約倉及基本單位後才開始新系統出貨。
3. **倉務操作員**在確認前打開「載入完整出貨庫位摘要」，逐行對實物、庫位、批號、效期及數量，另核對收件地址、包裹及追蹤號碼。首批確認後，**倉務主管**對送貨單和庫存異動，**Sales**對 SO 履約及餘量，**財務**對可開票出貨和舊發票清單。記下單號及簽認人。有差異先停受影響的單，交 PM 走切換決策。

## 誤出貨／退貨

- **尚未送出確認且仍是草稿**：暫停交運。地址或物流資料錯，可修正草稿。實物、批次或數量錯，由主管核對原揀貨，確認貨物回原庫位／批次後，按可用的取消流程處理並重新履約。取消出貨草稿後，原實揀紀錄仍在。
- **已出貨或實物已交運**：先攔截未交出的貨，將已尋回或退回的貨暫放隔離區，保留批號並記錄去向。通知 Sales 跟客戶或承運商確認，財務暫停該單開票或查明既有發票狀態。首期無出貨沖銷、退貨、貸項或退款流程。實物到倉後，僅由授權庫存主管依實收、品質及批次做必要調整，記下核准及異動號。庫存調整不會回復 SO 已履約量或發票。Sales、財務各自對帳並簽認，再由倉務主管結案。

## 結果不明

同一登入及瀏覽器分頁留在原出貨單，記下原操作號，按「查詢原確認結果」。草稿另用「查詢原草稿操作」。成功後核對同一出貨單、扣帳及 SO。只有畫面明確顯示原確認失敗、仍為草稿，且主管確認沒有出貨扣帳，才按「已核對失敗結果，重新準備確認」。仍處理中、查不到或權限失效時，交當班主管及系統支援用原單及原操作查證，暫停交運、改單、另建單或補庫存。

**值班與紀錄**：兩倉各有操作員及正副主管。主管接報後隔離實物、開事件編號，請 Sales／財務對本身紀錄。系統支援處理查證，主管負責結案與換班交接。角色的人名及聯絡方式由 Sam 確定。每個受影響的 SKU／庫位／批次記一列，同案用同一事件編號。暫不知批號或異動號可留空，確認後補齊。用 [例外登記 CSV](03-exception-log-example.csv) 留內部紀錄，證據欄只填受控連結或代號。
