# Fulfillment 正式資料準備指引

**要交什麼**：請 Sales 交一份已確認歸屬的新系統訂單清單，每列一張 SO，含舊單號（若有）、新單號及指定履約倉。Sales 的 CSV 由 Sales 負責。Fulfillment 從已確認、已有可用預留的 SO 建立工作，現行版本沒有履約或出貨 CSV 匯入／預檢入口，因此無匯入範本、檔案大小、分檔或預檢結果。已出貨及部分出貨的舊單照切換分流清單留舊流程，勿把舊出貨帶進新系統。

**前置次序**：先啟用貨品及基本單位、倉庫、庫位及客戶。批次貨核對追蹤設定、批號及效期。客戶要有有效送貨地址，選用聯絡人時也須有效。完成期初庫存對帳和簽核，按 Inventory 切換程序結案，再由 Sales 確認新系統訂單及預留。部署負責人確認已啟用履約流程，倉務用自己的角色讀回履約佇列。

| 畫面要填或選的項目 | 要求及合成例子 | 常見錯誤 |
| --- | --- | --- |
| SO、計劃行及數量 | 必填。從佇列選 `DEMO-SO-001`，以基本單位 EA 填數量 `2`，只填本次要出的量。 | 填成 2 箱、超過可用預留、拿錯履約倉。 |
| 分配庫位／批次、實揀量 | 必填。用推薦分配，核對 `DEMO-PICK-A`、`DEMO-LOT-A1` 和效期，再輸入實揀量。短揀必填原因。 | 把其他倉、不同批號或未揀到的貨算入。全部揀不到時用履約取消。 |
| 送貨地址、聯絡人 | 地址必選目前有效的客戶送貨地址，例如「示範收貨點」。聯絡人選填。 | 用錯客戶地址或把資料寫到備註。找不到地址時交 Customer 維護，再重新載入。 |
| 物流商、追蹤號碼、包裹數 | 選填。例「示範配送」、`DEMO-TRACK-01`、`1`。商名與追蹤號各最多 190 字，包裹數填正整數。 | 把 0 或小數填作包裹數。 |
| 總重量、重量單位、備註 | 選填。例 `1.25 KG`。重量為正數，最多 14 位整數、6 位小數，單位選 KG 或 G。備註最多 2,000 字。 | 只填重量沒選單位，或重量空白仍留單位。出貨日由系統在確認時保存。 |

**逐筆及核對**：每張出貨草稿補送貨及物流資料估計 1–2 分鐘，另計實物揀貨。確認前載入完整庫位摘要，核對地址、倉庫、批次和實揀數量。確認後用同一出貨單號對 SO 已履約量、送貨單及庫存發出異動。差異先暫停同單作業，按切換卡查證。

**開工前請確認**：Sam 指定截數時間及每倉倉務正副值班，Sales 確認每單歸屬及履約倉，Customer 確認缺地址由誰補，財務確認錯單暫停開票的聯絡方式。
