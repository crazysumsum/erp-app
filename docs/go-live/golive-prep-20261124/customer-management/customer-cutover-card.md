# Customer 切換日與例外操作卡

| 時點／負責人 | 操作與完成條件 |
|---|---|
| 截數前／業務資料負責人＋財務 | 封存交接版客戶清單，記下時點、檔名、總列數及分檔數。標明哪些客戶要開票、下單、送貨，以及各自的預設幣別、條款、帳單與送貨地址。新變更另登補錄單，避免兩邊同時改。 |
| 載入前／管理員 | 貨品／倉庫／庫位先完成；建立正式啟用幣別、條款和用到的分類／負責人，驗證帳號、裝置、權限、匯入目錄及背景工作。正式 CSV 只放受控位置。範本裡的 DEMO 客戶、幣別和條款值按正式清單替換，勿匯到正式庫。 |
| 載入／客戶管理員 | 用「僅新增」上傳。核對總列數＝有效＋警告＋無效。無效列先修，警告逐項簽認。由獲准帳號確認，按環境規則啟用或完成審批。保留匯入工作編號及下載結果。 |
| 放行前／客戶管理員＋財務 | 按工作結果對成功、失敗、略過數量及客戶代碼。**所有會開票的客戶逐一確認有有效預設帳單地址**；會送貨的核對有效送貨地址及聯絡人。抽查不同幣別／付款條款的客戶，做下單→出貨→開票確認；依上線版驗收，沒有預設帳單地址的發票應被拒。簽認後才交財務載入期初應收、Sales 載入在途訂單。 |
| 出現例外／當班管理員 | 先隔離待處理客戶／單據。缺帳單地址時，由業務確認地址、管理員在客戶詳情加「帳單」用途及預設，財務讀回後才重試確認。缺送貨資料先補再出貨。條款缺失或不可計算時由財務按核定日期填到期日，不替客戶猜值。 |
| 匯入結果不明／客戶管理員 | 用同一工作編號回查狀態及客戶代碼、下載結果，必要時請管理員協查；等結果確定後只補缺少或失敗的客戶。已成功的資料以受權操作逐項更正。 |
| 誤出貨、退貨或退款／Sales、Fulfillment、財務 | 停止後續作業，通知對應模塊當班負責人，按切換計劃走既有核准人工流程。Customer 僅核對主檔／地址／聯絡人；有引用的客戶保留資料，不用刪除或新建重複客戶來抵銷交易。 |

**例外紀錄**：發現時間、客戶代碼、工作／訂單／出貨／發票號、原狀態、原因、已核對結果、責任人、核准人、處理結果與關閉時間。記錄中只放必要聯絡資訊，不記密碼、完整銀行資料。

**版本提醒**：預設帳單地址是正式上線必備規則。11-24 基準 `c6df403e` 的 CSV 已能帶入 `billing*`，發票確認的 G5 閘門須在上線版驗證，不能用這次 CSV 預檢代替。
