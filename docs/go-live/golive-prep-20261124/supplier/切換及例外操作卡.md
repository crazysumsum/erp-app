# 供應商切換日操作卡

| 何時／誰做 | 操作及完成證據 |
| --- | --- |
| 開始前／營運、Customer、安全及帳號管理員 | 核對 Supplier 與 Customer 共用的加密及查找金鑰一致、備份各自可取用、服務健康。確認匯入目錄屬這個環境且僅服務帳號可讀寫，預檢、匯入、清理背景工作已啟用。只記通過結果，不記金鑰。 |
| 開始前／帳號管理員及採購主管 | 分別用獲核准裝置驗證匯入者、審批者及銀行資料維護者能執行職責。確認付款條款和幣別目錄已啟用，採購已定好首日啟用名單及審批人。 |
| 截數時／資料負責人 | 凍結來源清單，記截數時間、檔案版次、總列數及唯一 Code 數。正式檔放公司受限位置。截數後更動另記，按批准的方式補入 ERP。 |
| 匯入／指定匯入人員及覆核者 | 用「只新增」上傳，覆核預檢總數和每個警告，修正錯誤後再確認。依核准名單先存草稿或送啟用，設定要求審批時由指定人處理。每檔保留工作編號、總數、覆核者與逐列結果。 |
| 放行／採購主管 | 核對 Code、啟用狀態、幣別和條款。先補首日會用的供貨關係，再試選一家啟用供應商及對應 SKU，確認封鎖供應商無法選作新採購。用結果 CSV 核銷來源清單後簽核。 |

**例外**

- 上傳後長時間卡在預檢或排隊，先記工作編號和狀態，請營運查背景工作。結果未明時暫停重送和確認，以工作頁與供應商列表查明哪些列已處理。
- 公司名稱、代碼或銀行資料有疑問，先通知採購／財務覆核。若需阻止新採購，由有權人透過封鎖處理，記原因並核對狀態。已引用的 Code 或未完成採購單不可用刪除或封存替代更正。
- 應付付款、退貨或沖銷超出首期流程時，交財務或採購按受控流程處理。記日期、Supplier Code、原單號、原因、負責人及處理結果，銀行明文留在授權渠道。
