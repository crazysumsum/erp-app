# 12/08–12/10 應付驗收操作卡

**狀態為待執行。** 只在已部署應付候選版的總預演庫使用。記下候選 SHA、業務日期、收貨號、發票及付款號。以下金額均為 HKD。入帳、改價與付款各用其專用角色，另設供應商管理員處理狀態。

準備啟用供應商 `DEMO-AP-01`，獨立的已完成 PO，兩張整張已確認收貨，對應未稅行金額分別為 125、90。另備一個無未付發票的合成供應商 `DEMO-AP-PRE`。由應付查閱角色記下兩者起始帳齡為零。預演資料按操作卡分別保存實際行金額、收費及原因，所有轉帳參考使用 `DEMO-` 開頭。

| 步驟／操作者 | 操作 | 必須讀回的結果 |
|---|---|---|
| AP01 入帳 | 「應付發票 → 登記應付發票 → 由收貨開票」。按供應商篩選，勾選上述兩張整張收貨，依收貨之後且不晚於業務日的日期建草稿，供應商發票號 `DEMO-GR-01`。 | 同供應商、同幣別，兩個來源各一筆；未調整前合計 215。保存草稿 ID 及原採購價。 |
| AP02 入帳／改價覆核 | 一般入帳帳號檢查行改價受限。由另有 `ap.invoice.price.override` 的帳號將第二行原件實際金額填 95，先留空理由確認受阻，再填「合成發票逐行核價」。按原件加運費 5。 | 第一行 125、第二行 95、費用 5，與原件 225 完全一致。重開仍可見調整依據與兩張來源。確認只取得一個 ERP 發票號。 |
| AP03 入帳 | 選「無採購單發票」，選同一啟用供應商、HKD、原因及到期日，登記服務費 100，合成原件 `DEMO-EXP-01`。存草稿、確認，重新開詳情。 | 無 GR 來源，費用行 100。帳齡多兩張已確認發票共 325，分別未付 225、100。 |
| AP04 供應商管理員 | 使用另設且沒有未完成 PO 的供應商，先立一張已確認未付的無採購單發票 10；將供應商移至產品允許申請封存的狀態，嘗試封存。 | 拒絕原因指向應付未付額，供應商未被封存、未付 10。保存訊息及來源發票，避免被未完成 PO 的限制混淆。 |
| AP05 付款 | 從 AP03 的帳齡列或發票詳情「登記付款」，用只有 `ap.view` 和 `ap.payment.mgmt` 的角色。確認供應商及 HKD 帶入，填業務日、轉帳 325 及參考 `DEMO-PAY-01`，存草稿，再確認取號。 | 確認前後查原草稿及付款號，同一筆付款可核銷 325。獨立搜尋供應商需要 `supplier.view`，角色未授予時有提示。 |
| AP06 付款／覆核 | 先核銷 125 到第一張，重開付款及發票；再核銷第一張剩餘 100、第二張 100。 | 中間付款可核銷 200，發票各餘 100，帳齡兩張共 200。完成後付款餘額 0、兩張發票未付均 0，該供應商 HKD 帳齡降至零。保存三筆核銷與前後帳齡。 |
| AP07 付款／供應商管理員 | 用具 `supplier.view` 的付款角色，在啟用且沒有同幣別未付發票的 PRE 建預付款草稿 15。主管將 PRE 停用或封鎖，先重開原草稿確認，再嘗試新建預付款。 | 兩次均被拒，原草稿不取號、無新增已確認付款。用 AP04 尚欠 10 的非啟用供應商，由該筆帳齡進入付款 10；應可清償既有債務及核銷至零。 |
| AP08 入帳 | 在獨立草稿查發票日期，發現錯日就取消原草稿，以正確日期重建並重填金額及費用。改到期日先留空原因，再填理由；到期日不得早於發票日。嘗試以業務日次日開草稿。 | 發票日期在草稿中固定；兩個草稿 ID 可區分，取消單不計帳齡。到期日改動有原因才可儲存；未來發票日期建立被拒。若升級種子已有未來日草稿，確認取號被拒且仍可取消；欠該舊草稿時將此子項記「缺歷史種子」。 |
| AP09 入帳／供應商管理員 | 在啟用且沒有其他未付的獨立供應商先建無採購單發票草稿，再由主管停用。試確認舊草稿及另建無採購單發票。 | 確認與新增都被擋；原草稿仍可取消，應付帳齡沒有新債務。 |

**例外單據。** 用一張收貨被拆開開票、一張整單折扣及一張截數前舊欠的合成原件，分別在例外台帳記錄舊號、GR、金額、到期日、責任人及處理結果。覆核這三筆未在 ERP 新增重複債務與出款。若付款回應不明，由原帳號在原分頁「重試原操作」，以原付款號、參考及金額對帳。

**結果記錄。** 各步附實際版本、單號、角色、預期與實際餘額、通過或受阻、證據位置。發票與付款交應付負責人，供應商狀態或封存限制同步交供應商負責人。依據為《切換及例外操作卡》、《應付角色配置》和已接受的應付範圍 r10 第 3.3 節。[應付準備文件](https://github.com/crazysumsum/erp-app/tree/7b6a38a34d06b1faa1390ce7d35b578f64d4def7/docs/go-live/golive-prep-20261124/ap) · [應付範圍 r10](https://github.com/crazysumsum/erp-app/blob/c5ee54ea/docs/accounts_payable_management/ap-minimal-scope-20261124/SCOPE.md)
