# 切換日與設備例外操作卡

## 截數前與切換日

1. **Sam／部門主管**確認角色對照表及採購建單、審批分工。指定正副管理員。正管理員逐筆建帳及核准實際使用的設備，副管理員逐筆覆核角色、代班審批和接手緊急事件。各用自己的帳號和已核准設備。
2. **部署負責人**核對正式環境與資料庫，完成 migration。全新庫用既有 `createUser.js` 建立首位管理員，從提示輸入密碼。管理員用正式瀏覽器登入一次送出待審申請，部署負責人用 `approveDevice.js --list` 核對後只核准本人那一筆。管理員重新登入，在角色頁重開確認所需權限，然後開通副管理員並確認他也能審批。
3. **正副管理員與使用者**每批約 5 人。私下交付各自的初始密碼。使用者用日常瀏覽器登入送審，管理員核對申請人及設備後核准。使用者重新登入，依提示改密，再用新密碼登入並核對工作頁。臨時密碼 72 小時有效。若共用同一個對外 IP，上一批最後一次登入後預留約 10 分鐘。若遇 429，依系統等待時間接續。每批估 10–15 分鐘，四批加等候約 70–90 分鐘，另計角色設定與管理員開通。
4. **副管理員**對照名單記錄帳號、核准角色、設備識別碼、改密後登入結果及覆核時間。確認可開啟應有工作頁，抽查無權限的管理頁會拒絕。未完成的帳號標記原因和負責人，由主管確認相關班別有人能接手。

## 緊急核准與撤銷演練

- **管理員換機或清除瀏覽器資料**。在預演庫用測試管理員送出新設備申請，由副管理員核對本人及設備後核准。若全部管理員都無法登入，由部署負責人依既有 CLI 程序核准已核實的待審申請，確認重新登入與審批功能恢復。記錄操作者、時間、帳號、設備 ID、理由和結果。
- **設備遺失或遭竊**。在預演庫用一般測試帳號及兩個瀏覽器設定檔模擬。IT 核對帳號、設備識別碼與系統綁定編號，由具設備管理權限的值班人員重新驗密，透過既有撤銷介面處理該筆綁定。核對該設備再次登入遭拒，另一台已核准設備可重新登入。若無法即時撤銷，可先停用受影響的一般帳號，處理完才重新啟用。若涉及最後一位管理員，交部署負責人按緊急程序處理。記錄設備、停用／撤銷時間、操作者、確認結果及後續負責人。

以上為預演與正式切換的操作程序。首位管理員核准流程已有全新庫 UAT 證據，撤銷演練結果須由值班人員在切換前交回。
