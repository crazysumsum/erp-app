# 在途採購單資料準備

交一份由採購主管及兩倉覆核的「在途採購單交接表」。每列是一張舊採購單的一筆未收明細。刪掉範例後再填正式資料，保存在內部交接位置。採購單與收貨歷史不移轉。現行版本沒有採購 CSV 上傳入口，這份表供逐張建單及簽核。

| 欄位 | 必填、格式與常見錯誤 |
| --- | --- |
| 舊單號、舊行號 | 必填，例如 `DEMO-LEGACY-001`、`1`。同一舊單可有多行，舊單＋行號不可重複。 |
| 入帳路徑、採購負責人、覆核狀態 | 必填。填「舊系統結清」或「新系統重建」，同一舊單各行須一致。負責人填指定同事，狀態從「待覆核」開始，簽認後更新。 |
| 供應商代碼、SKU、收貨倉 | 必填，填已核對的代碼，例如 `DEMO-SUP-A`、`DEMO-SKU-A`、`DEMO-WH-A`。勿填名稱或猜配相似編碼。 |
| 採購單位、基本單位、每採購單位等於基本數 | 必填，例如 `BOX`、`EA`、`24`。按該 SKU 的換算，未收餘量換算後必須是整數基本單位。 |
| 原訂數量、截數前淨收數量、已取消或結清數量、未收餘量 | 必填，同一列全用採購單位，最多六位小數。未收＝原訂－已過帳淨收－已取消／結清，例如 `10−4−1=5`。零餘量不列，負數或單據未過帳先查差異。 |
| 幣別、單價 | 重建必填，例如 `HKD`、`0.12`。單價按採購單位、最多四位小數；零價在畫面填 5–500 字的原因。不要把全行金額當單價。 |
| 新單訂單日、預計交期 | 重建單日期必填，交期選填，均為 `YYYY-MM-DD`。交期不得早於新單日期，有逐行交期就填在明細。 |
| 新採購單號 | 建立前留空，儲存後抄入系統編號，同張舊單各行填同一新單號。 |

**交檔與順序。** UTF-8 CSV、保留欄名。一份總表即可，交接表沒有系統檔案上限；畫面每張採購單最多 100 行，超限先交主管定案。先核對啟用供應商、SKU 及換算、幣別／付款條款、兩倉／庫位與操作權限，期初庫存對帳簽認後，按切換名單逐張建單。

**畫面及核對。** 在「採購單 → 新增採購單」只輸入未收餘量。指定採購員，按主檔核對付款條款、訂購地址及表頭交期。備註記舊單號；若須審批，指定另一位審批人。估每張一至兩行約 3–5 分鐘，每多一行約 30–60 秒，審批等待另計。主管核對舊／新單與行數，按供應商、倉庫、SKU 及基本單位比對未收量，按幣別核對金額。對不上先留草稿並標記，回查舊收貨及關單紀錄，覆核後才提交。

**請業務先確認。** 截數時點、新舊編碼與單位換算、各舊單入帳路徑、負責人及獨立覆核人，並指定留舊系統的收貨如何只一次銜接新庫存。

**範本驗證。** 本機驗過 3 列、2 張舊單，且每張只有一條入帳路徑。兩筆重建明細通過現行採購單欄位及單位換算檢查，為 120 和 22 個基本單位。採購沒有 CSV 上傳預檢，範本用於人工建單。
