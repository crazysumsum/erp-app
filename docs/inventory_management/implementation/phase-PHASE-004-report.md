### Product scope and invariants

`InventoryTransferService` implements `dispatch`/`receive` and caller-owned transaction variants. Dispatch debits each source bucket's unallocated quantity and sets full line In Transit; Receive validates the exact complete line ID/quantity set, owned Active destination Bin, immutable SKU/Lot/Expiry and kept stock status or Quarantined plus new reason. Keeping existing Quarantined/Damaged status needs no new status-change reason. Physical Receive preserves complete quantities even if expiry elapses; existing Sales eligibility remains separate, and this Task does not invent a Receipt expiry exception or adjust history.

Existing lock orchestration sorts both Warehouses/Controls, all relevant Bins/Lots/Balances, source Reservations and Transfer root. Source SKU buckets are held to evaluate post-Dispatch eligible quantities across all outstanding Reservation thresholds; Reserved counters equal the held outstanding sum. Late new reservations or changed document preview cannot authorize an unlocked scope and fail safely. Repeated lines sharing a bucket use cumulative working quantities/versions. Source/destination ownership is checked before Balance upsert and again under held rows; Bin Stocktake guards apply to the Bins actually changing On Hand. No new shared lock framework, schema migration, dependencies or HTTP/UI are introduced.

Each posting has one group of paired legs per line: Dispatch BIN OUT/source + In Transit IN/destination; Receive In Transit OUT/destination + BIN IN/destination. Stock before/after, versions, SKU/location/Lot snapshots, operation, actor/time and Transfer references persist with line/header state and mandatory Audit. FIFO anchors clear on zero and start on zero-to-positive. Required Audit or intermediate writes failing rolls back the complete transaction. Dispatch/Receive separately replay the original immutable operation receipt after subsequent workflow state changes; altered payload or cross-command reuse of the same source event conflicts. Raw Movements remain immutable.
