# 首期預演操作卡

**11/26 正式驗收登入**請使用正式庫八個角色的專用瀏覽器設定檔。帳號對照、裝置未核准時的逐步處理與私下交接方式，見 [正式驗收登入操作卡](formal-20261125-checklist.md)。

每次從 UAT 前端 http://127.0.0.1:5273 開始，分別使用已核准的銷售、倉務、採購及採購主管瀏覽器。每一步先在目前頁面做 Playwright snapshot，按該快照的 ref 執行 click、fill 或 select。Quasar 選單點開後選擇相符的 option。點擊前核對單號；跨頁後重取快照。每步保存單號、狀態、金額或庫存、截圖、console warn 與 requests（含 4xx/5xx 及 transport failure）。密碼由私有檔讀入，登入及重驗畫面不留輸入截圖或請求本文。

以登入銷售、建立兩行報價為例，以下是可直接交給 playwright-cli run-code 的單一操作。請先在頁面選好客戶。日期使用當次業務日期，有效至不得較早。
```js
async page => {
  for (const [i, sku, unit, qty, price] of [[1,'UAT-A1','BOX','2','100.00'],[2,'UAT-C1','EA','10','12.50']]) {
    await page.getByLabel('搜尋 SKU',{exact:true}).fill(sku);
    await page.getByRole('option',{name:new RegExp('^'+sku+' —')}).click();
    await page.getByLabel('銷售單位',{exact:true}).click();
    await page.getByRole('option',{name:new RegExp('^'+unit+' —')}).click();
    await page.getByRole('button',{name:'新增明細',exact:true}).click();
    await page.getByLabel('數量 '+i+' *',{exact:true}).fill(qty);
    await page.getByLabel('售價 '+i+' *',{exact:true}).fill(price);
  }
}
```

## 帳號及資料載入

第一個帳號 uat-admin 用既有 system-admin。其餘七個角色名稱及帳號名相同，顯示名用正式建庫清單中的中文名稱。以 /system/roles 建立並逐一配置列明的權限，以 /system/users 建帳，再於 /device/approvals 核准各自的瀏覽器。採購建立與審批分開；低效期放行由倉務主管執行。

先啟用 HKD、USD、UAT-NET30（30 日）和 UAT-COD（即日）。跟隨 inventory-instructions.md 設定單位、分類及品牌，再上傳 01 貨品檔並完成各 SKU 單位、批效與啟用。以 04 從客戶匯入頁預檢三筆並確認、啟用、重查地址和聯絡人；以 05 從供應商匯入頁預檢兩筆並確認為啟用。採購單位取自 SKU；正常流程用 A。封鎖例外用 B，先以啟用狀態批准其 PO，再由具 supplier.approval 的管理員於核准設備封鎖 B 並填原因及密碼，才以倉務操作收貨。套用 06 時在 /inventory/warehouses 依倉庫代碼各建一次，再選倉逐筆「新增庫位」。06 是頁面輸入清單。在期初匯入頁先用 03 確認無異動，再用 02 核對 8 筆、552 EA。11/25 驗收庫重新載入上述正式樣本。

## 實際執行入口

在 UAT 的 preparation 目錄執行 node order-steps.cjs，一次選一個案例。S01 不加參數；S02 加報價數字 ID；S03 加完整 SO 單號與批次 1 或 2；S04 加履約 ID；S05 加履約 ID 與批次；S06 加履約 ID。S07 用第二批重做 S03–S06。P01 不加參數；P02 加完整 PO 單號。每步按上表完成庫存頁、數量及單據的獨立核對後才登記 PASS。S01 儲存後會顯示報價號；由報價列表使用該號點「查看」進詳情才有「發出報價」。S02 轉單後須點「查看銷售訂單」才進確認頁。

財務頁面的逐步操作如下。node ar-step.cjs S08 或 S09 後加完整出貨單號；S10 不加參數；S11 加收款數字 ID、首張發票數字 ID 及完整號碼、次張發票數字 ID 及完整號碼；S12 加 NORTH 數字 ID。使用 /ar/invoices/new、/ar/receipts/new、/ar/aging。每一步只在對應程式合併並部署且前一步有實機單據時執行。草稿已建立或同一筆確認結果未明時，從原單接續或查詢原操作，避免再建一張。

收款範圍依 11/20 決定，只驗有未收發票的客戶及幣別。開票前收款由人手記錄，開票後補登；詳見 ../known-limits.md 第 16 項。
