# 收貨沖銷

- 具備 `purchasing.view` 及 `inventory.adjust` 的使用者可從已確認或部分沖銷的收貨單開啟表單。預覽以當前交易檢查整張收貨單的有效應付佔用，並列出每個明細扣除已沖銷及已過帳退供後的可沖銷基本數量。過帳時重新檢查版本、佔用、數量及原收貨庫存。
- 過帳須驗證登入密碼及裝置簽章。HTTP 指紋與永久操作記錄均使用相同的 `eventId`，業務指紋排除密碼。瀏覽器收到不明結果時，可依原事件查詢或沿用原內容重試。
- 過帳後保留原始收貨數量，詳情另外列出累計沖銷數量及各張沖銷單。部分沖銷後，應付開票來源以更正後淨量計算，實物退供由其流程另記。

## 交易競爭

不同採購單的收貨單同時新增各自的第一張沖銷單時，MySQL 的空索引區間可能因序號的當前讀取產生死結。服務會將此回傳為 `409 CONCURRENT_OPERATION` 並回滾整個交易（包括庫存異動）。重新載入資料後可重試。技術評審在私有 MySQL 確認了這個行為，接受以現有容量處理。

## 發布依賴

沖銷入口的正式合併版建在已合併的應付佔用 provider 及其 schema、退供已過帳讀取與 schema 之上。成本啟用須等庫存端完成鎖序修正與各寫入流程的成本接線，再按 Inventory 的啟用及勾稽流程部署。綜合驗證候選沿用 CI 提供的正式合併順序重新建立。
